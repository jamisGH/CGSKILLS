# 最終驗收流程

執行跨 Skill 或發布前 QA 時讀取本檔。

1. 鎖定交付版本、範圍與必要驗收項，避免驗錯版本。
2. 建立可追溯矩陣：每個關鍵主張對應來源、責任 Skill、狀態與位置。
3. 檢查：結構完整、來源有效、跨段邏輯一致、品牌與語氣符合要求、格式可用、敏感資料處理正確、附件與輸出齊全。
4. 若為 DOCX/PDF，要求 `cg-word` 的結構與逐頁視覺 QA 證據；不可只靠文字抽取。
5. 對缺陷分級並指定責任 Skill；完成修正後重新檢查受影響項與必要回歸項。
6. 彙總狀態：有 critical/major 缺陷為 `FAIL`；必要檢查無法完成為 `BLOCKED`；其餘必要項全通過才為 `PASS`。
