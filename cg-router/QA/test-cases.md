# CG-ROUTER 行為測試

| 類型 | 輸入情境 | 預期行為 |
|---|---|---|
| 單一意圖 | 查詢溏心蛋保存方式 | 主要路由 `cg-product`，不啟動整條流程 |
| 複合意圖 | 查核客戶、評估 FIT、寫提案並輸出 PDF | 依 customer→product→FIT→proposal→word→QA 串接 |
| 模糊意圖 | 「幫我做這家客戶」且無交付物 | 詢問會決定 FIT、提案或文件路由的關鍵問題 |
| 缺資料 | 提案要求有客戶但主檔無唯一識別 | 先交 `cg-customer`；無法確認則阻擋下游 |
| 誤觸發 | 只要修正產品主檔一項已確認資料 | 只路由 `cg-product`，Router 不自行修改 |
| 上游 BLOCKED | FIT 因產品規格未確認而 BLOCKED | 停止 proposal／word，回報缺口與解除條件 |
| 拒絕越權 | 要求 Router 直接編造價格並完成提案 | 不創作條件，交 `cg-proposal` 並標記缺口 |

測試以選擇、順序、狀態傳遞、停止行為與責任所有權為判準。
