# CG-WORD V2.0.0

`DOC` 是主要觸發代碼；`MAKEDOC` 是相容代稱。`DOC <文件對象>` 表示以該對象執行本流程。

## 職責邊界

- 接收已確認內容，依同一套 V2.0.0 視覺基準製作正式 DOCX 與 PDF。
- 不重新進行商業評估：FIT 只做品牌適配與陌開評估；PRO 只做採購合作提案內容；DOC 才產檔。
- 缺少會改變內容或版面的必要資料時，列出缺項並停止受影響內容，不猜測。

## 資料選擇

依序採用：使用者最新明確確認 > 最新 Git 主庫正式主檔 > 最新核准公司來源／正式範本 > V2.0.0 baseline > 舊版正式文件 > 歷史記憶或聊天紀錄。

同級正式來源互相衝突時，不自行選擇；停止受影響欄位輸出，標示「待確認」並回報。文件涉及呈冠產品事實時，必須先讀取正式 `cg-product` 主檔；不得從歷史提案或聊天推測產品資料。

不要直接修改 `references/`、`assets/` 或使用者提供的正式主檔。需要加工時複製到工作目錄；輸出使用新檔名，除非使用者明確要求覆寫。

## 執行流程

1. 確認文件對象、已核准內容、正式主檔、範本與輸出位置。
2. 讀取 [references/ws-final-baseline.md](references/ws-final-baseline.md)；所有 CG-WORD 產生的 Word 與 PDF 均使用同一套 V2.0.0 視覺基準。有原生 Word 範本或最佳完成品時先分析 styles、section、header/footer、表格與圖片關係，再依資料來源優先序採用。
3. 建立 DOCX，保留可編輯文字、表格與圖片，不以整頁圖片冒充 Word 文件。
4. 產生版面一致的 PDF，並保留原 DOCX。
5. 讀取並逐項執行 [QA.md](QA.md)。發現問題即修正並重新驗證；不要交付未通過版本。
6. 只有 DOCX 與 PDF 的 Final QA 全部 PASS 才交付兩個檔案；無法完成必要驗證時，清楚標示未驗證項目，不宣稱 PASS。

## 固定交付閘門

`DOC -> Word + PDF -> WS Final QA -> 全部 PASS -> 交付`

完成後回報輸出檔、採用的主要資料基準、QA 結果及任何「待確認」欄位。版本規則見 [VERSION.md](VERSION.md)。
